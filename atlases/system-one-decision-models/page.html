The primitive

Why RLHF chatbots break inside software

Conversational AI feels brilliant in chat because RLHF optimizes it to satisfy a human watching the screen. Drop that same model into unattended control flow, Diogo Almeida warns, and sporadic variance ruins automation: an unpredictable 5% failure rate forces a human reviewer back onto 100% of outputs.

“I often call it you get Einstein ninety five percent of the time, but Mr Bean five.”Diogo Almeida · I love you so jevving much · 00:08:57

Training specifically for narrow, dependable judgment turns model invocation from an unreliable assistant into a deterministic building block inside ordinary programs—like the blue LED transforming lighting rather than adding another filament:

“This is kind of conceptually adding a fourth semantic logic gate.”Diogo Almeida · I love you so jevving much · 00:12:12

In the database

Replace embeddings and vector DBs with SQL

Typical retrieval stacks encode documents into embeddings, store them in a vector database, run approximate similarity search, and feed candidates to a reranker that asks a yes/no question anyway. At moderate dataset sizes, Roberts skips the entire stack and asks the decision model directly:

“But with Jeff, we basically take out all the embedding steps.”Scott Roberts · Autocomplete for Actions · 00:08:03

Wired into DuckDB as a scalar SQL function, Jev screened 117 resumes in 2.3 seconds—catching semantic disqualifiers (like fraud-prevention work vs. actually committing fraud) that keyword and cosine retrieval miss:

“So this is against a DuckDB, where we have a function.”Scott Roberts · Autocomplete for Actions · 00:09:24

At the edge

Grounded world knowledge

Web grounding fixes uncalibrated overconfidence

Fast decision models still fail catastrophically when asked about current events outside their weights—returning stale guesses with misplaced certainty:

“And so it's kind of crazy that you would use a decision model in your workflow that has like almost no understanding of like what. And so this is where we think that like not only is it wrong, but also its confidence is too high.”Devin Gupta · The first Grounded Decision Model · 00:00:55

Parallel grounds each decision call against a ~100B-page live web index, turning guesswork into calibrated probabilities and source citations under one second at $1 per 1,000 requests—powering 100k-row market enrichment, KYC checks, and instant news routing:

“What is correct is much more confident that's correct if you use actual grounding to ground your decision. So there's like a whole set of things here that unlocks, and specifically like. Calibration is the important thing about good decision models.”Devin Gupta · The first Grounded Decision Model · 00:01:50

Where it lands

Uncontested primitive, three runtime surfaces

System One decision models are the conference’s cleanest uncontested architectural category. Every speaker converges on sub-second latency, typed non-conversational outputs, and calibrated confidence; talks diverge solely on where the call runs—inline in UI and DuckDB SQL, inside edge Workers, or backed by a live web index.

  • Reserve frontier LLMs for synthesis: move binary gates, multi-class routing, and row scoring onto single-pass decision calls (00:01:42, 00:07:50).
  • Delete redundant RAG plumbing at medium scale: direct SQL row judgment beats maintaining embeddings and vector indexes when sets fit in a batch query (00:08:03, 00:09:24).
  • Ground external facts live: never trust an ungrounded model’s confidence score on current world state; attach live search and citations (00:01:50, 00:05:45).
For TheFocus.AI: When auditing client workflows, inspect every LLM call inside an if, switch, or filter step. Replacing slow chat completions with typed System One calls inside SQL, edge routing, or web-grounded APIs cuts latency and cost by 10–100× while eliminating fragile prompt parsing.
